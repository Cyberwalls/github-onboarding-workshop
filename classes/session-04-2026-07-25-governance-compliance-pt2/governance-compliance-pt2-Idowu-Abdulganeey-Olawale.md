## Key Concepts I Learned

* Security governance in Azure involves establishing and enforcing standards that help organizations maintain secure, compliant, and well-managed cloud environments.

* Azure Policy can be used to create, assign, and enforce policies that ensure Azure resources comply with organizational and regulatory requirements.

* Resource locks help protect critical Azure resources from accidental modification or deletion.

* Microsoft Defender for Cloud provides security posture management, recommendations, and insights that help organizations identify and remediate security weaknesses.

* Regulatory compliance management helps organizations assess their cloud environments against regulatory standards and identify areas that require improvement.

* Role-Based Access Control (RBAC) supports the principle of least privilege by ensuring users are assigned only the permissions required to perform their responsibilities.

* Access reviews and permission management can help organizations identify unnecessary or excessive access and maintain better control over privileged accounts.

* Azure Backup security features help protect backup data from accidental deletion, malicious activities, and ransomware attacks.

* Infrastructure as Code (IaC) security allows organizations to integrate security and compliance checks into the deployment process before resources are deployed into production.

## Lab / Hands-On Work

### What I did

I explored the concepts and tools used to enforce security governance and regulatory compliance within Azure environments.

The learning activities covered:

* Using Azure Policy to enforce organizational standards.
* Understanding how resource locks protect important Azure resources.
* Exploring Microsoft Defender for Cloud and its security recommendations.
* Reviewing security posture and regulatory compliance requirements.
* Understanding how RBAC supports least-privilege access.
* Learning how access reviews can help manage and reduce excessive permissions.
* Exploring security features used to protect Azure Backup environments.
* Understanding how security can be integrated into Infrastructure as Code deployments.

### What happened / Result

I gained a better understanding of how different Azure security and governance tools work together to maintain a secure and compliant cloud environment.

The learning path demonstrated that cloud security is not limited to responding to threats. Organizations can proactively reduce risks by implementing policies, managing access, monitoring security posture, protecting critical resources, and integrating security controls into the deployment lifecycle.

### Challenges I faced

One of the areas that required additional attention was understanding how the different governance and security services complement one another.

For example, Azure Policy, RBAC, resource locks, Microsoft Defender for Cloud, and regulatory compliance tools all address different aspects of cloud security. Understanding when and where to apply each control was important for building a complete security governance strategy.

## My Takeaways

The most valuable takeaway for me was understanding that effective cloud security requires a **proactive approach**.

Security governance should be integrated into every stage of cloud operations, from resource deployment and access management to continuous monitoring and compliance assessment.

I also gained a stronger understanding of the importance of the **principle of least privilege**, continuous security posture management, and automating security controls through policies and Infrastructure as Code.

These concepts are particularly important as I continue developing my skills in **Cloud Security and Cybersecurity**, especially in securing and governing cloud environments at scale.
